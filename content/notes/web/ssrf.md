# SSRF：让服务器替你访问内网

## 为什么值钱

一个 SSRF 的威力不取决于漏洞本身，而取决于**服务器站在哪里**：

```
互联网 → [你的浏览器]  ✗ 进不去内网
互联网 → [目标服务器]  ✓ 它就在内网里
```

所以 SSRF 本质是**位置平移**：把"从外网发请求"变成"从内网发请求"。

## 常见入口

| 功能 | 参数形态 |
|---|---|
| 图片抓取/远程下载 | `url=http://...` |
| Webhook 配置 | `callback=https://...` |
| RSS / 内容聚合 | `feed=http://...` |
| PDF 生成（HTML 转 PDF） | 内嵌 `<img src>`、`<iframe>` |
| 文件导入（URL 导入） | `source=http://...` |
| 代理/预览 | `target=...` |

PDF 生成器是常被忽略的 SSRF 入口：它由服务端渲染 HTML，页面里的资源请求全部由服务端发出。

## 判定：先分清盲与非盲

**非盲**：响应体直接返回目标内容 → 最容易确认。
**盲 SSRF**：只返回成功/失败，或完全无回显 → 需要带外通道。

带外验证的三种方式：

1. **DNS**：`http://<随机子域>.your-dnslog.com` —— 看 DNS 日志有没有请求
2. **HTTP**：自己的 VPS 起一个 listener，看有没有回连
3. **时间**：请求一个会挂起的地址，比较响应时长

## 协议面

| 协议 | 用途 |
|---|---|
| `http/https` | 基础，探测内网 Web |
| `file://` | 读本地文件（等价于 LFI） |
| `gopher://` | 构造任意 TCP 报文，可打 Redis/MySQL/FastCGI |
| `dict://` | 探测端口与服务 banner |
| `ftp://` | 部分环境可用来外带文件 |

`gopher://` 是 SSRF 里最强的协议，因为它能**发出任意字节**。这也是为什么防御要限制协议白名单，而不只是封 IP。

## 云环境：元数据服务

云主机上有一个特殊地址，能拿到实例身份凭据：

```
http://169.254.169.254/
```

- AWS：`/latest/meta-data/iam/security-credentials/`
- 阿里云：`/latest/meta-data/`
- 腾讯云：`/latest/meta-data/`
- GCP：需要 `Metadata-Flavor: Google` 头（默认禁止转发，但可绕过）

拿到临时凭据后，攻击者可以直接调用云 API。这是 SSRF 从"中危"变成"严重"的典型路径。

> [!WARNING]
> 测试云元数据时**只读取、不外传**，拿到凭据应立即停止并写入报告。使用凭据调用 API 属于越权操作，需要额外授权。

## 绕过 IP 限制

很多修复只做了字符串黑名单（`127.0.0.1`、`192.168.`），绕过方式非常多：

| 手法 | 例子 |
|---|---|
| 进制转换 | `2130706433`（127.0.0.1 的十进制） |
| 八进制/十六进制 | `0177.0.0.1`、`0x7f.0.0.1` |
| 短写 | `127.1`、`0.0.0.0` |
| IPv6 | `[::1]`、`[::ffff:127.0.0.1]` |
| 域名解析 | `localtest.me`、`nip.io` 直接解析到 127.0.0.1 |
| 重定向 | 自己的域名 302 到 `http://127.0.0.1` |
| DNS 重绑定 | 第一次解析返回公网 IP（通过校验），第二次返回内网 IP |

**DNS 重绑定**是最难防的：校验时解析一次，请求时解析一次，两次结果不同。

## 危害升级路径

```
SSRF
 ├─ 端口扫描 → 发现内网服务
 ├─ 读文件（file://）→ 源码/配置/密钥
 ├─ 打 Redis（gopher）→ 写 crontab / 写 SSH key → RCE
 ├─ 打 FastCGI → RCE
 ├─ 云元数据 → 临时凭据 → 云资源接管
 └─ 内网 Web 未授权 → 直接进后台
```

报告中应说明**走到了哪一步**，而不是笼统写"存在 SSRF"。

## 防御

1. **协议白名单**：只允许 `http/https`
2. **解析后校验 IP**：先 DNS 解析，判断结果是否在禁止网段，**并用解析出的 IP 发起请求**（防重绑定）
3. **禁止重定向**，或每跳都重新校验
4. **独立出口**：请求走专用代理/ NAT，与内网隔离
5. **元数据服务加固**：强制 IMDSv2（需要 token + PUT）、限制 hop limit
6. **不回显响应体**：只返回状态，降低信息泄露
7. 内网服务加认证，不依赖"外网进不来"

```python
# 关键校验顺序（示意）
ip = socket.gethostbyname(hostname)          # 1. 解析
if is_private(ip) or is_metadata(ip):        # 2. 校验
    raise Forbidden
requests.get(f"http://{ip}/", headers={"Host": hostname}, allow_redirects=False)
```

## 测试清单

- [ ] 所有接受 URL 的参数都测了吗（含 PDF 生成、Webhook）
- [ ] 支持哪些协议（`file://` 能否读文件）
- [ ] 302 跳转是否被跟随
- [ ] IP 黑名单能否用进制/短写绕过
- [ ] DNS 重绑定是否可行
- [ ] 云元数据是否可达
- [ ] 内网常见端口（6379/3306/8080/9200）是否可探
