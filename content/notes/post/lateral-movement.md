# 内网横向：立足点之后的路径

> [!WARNING]
> 内网横向是渗透测试中**风险最高**的部分：可能触发业务中断、账号锁定、告警风暴。必须提前与客户约定时间窗与禁止动作。

## 横向的三个前提

任何一次成功的横向，都要同时满足：

```
1. 网络可达（能路由到目标，或有一条隧道）
2. 有可用凭据（密码、哈希、票据、密钥）
3. 目标服务允许该凭据登录（权限、组策略、防火墙）
```

缺任何一条都不成立。所以横向工作的实质是**分别解决这三个问题**。

## 第一步：摸清网络位置

```bash
ip a; ip route
cat /etc/hosts
arp -a                     # 同网段还活着谁
cat /etc/resolv.conf       # DNS 域 = 域环境的强线索
netstat -antp              # 本机连出去过谁
```

判断自己在哪：

| 位置 | 典型特征 | 下一步 |
|---|---|---|
| DMZ | 双网卡、能访问内网但不能被内网访问 | 找通往内网的跳板 |
| 办公网 | 大量 445/3389、能解析内网域名 | 找域控与文件服务器 |
| 生产区 | 只有业务端口，横向困难 | 转向应用层凭据 |

## 第二步：凭据收集

优先级从高到低：

1. **配置文件**：`web.config`、`.env`、`application.yml`、数据库连接串
2. **历史命令**：`.bash_history`、`PowerShell` 历史
3. **内存与进程**：`lsass`（Windows）、浏览器保存的密码
4. **密钥文件**：`id_rsa`、`.ssh/known_hosts`、云厂商 AK/SK
5. **票据**：Windows 的 Kerberos 票据缓存

> [!NOTE]
> 凭据收集是"读"，不是"破解"。拿到哈希后是否离线破解，属于授权范围问题，需要提前确认。

## 第三步：隧道与代理

内网机器通常不能直连，需要把流量"送进去"。

| 工具 | 原理 | 适用 |
|---|---|---|
| `ssh -L/-R/-D` | SSH 端口转发 / 动态代理 | 有 SSH 权限时最省事 |
| `chisel` | HTTP 隧道，单文件 | 只有 Web 出网时 |
| `ligolo-ng` | TUN 网卡，透明转发 | 需要扫全网段时体验最好 |
| `frp` | 反向代理 | 需要长期稳定通道 |
| `proxychains` | 客户端代理链 | 配合上面的 socks |

```bash
# SSH 动态代理：本地 1080 变成 socks5
ssh -D 1080 -N -f user@jump-host

# 通过代理跑扫描（注意：-sT 才支持代理）
proxychains4 nmap -sT -Pn -p 80,445,3389 10.10.20.0/24
```

选择原则：

- 只要访问几个 Web → `ssh -L`
- 要扫网段 → `ligolo-ng` 或 `chisel` + `proxychains`
- 注意：**代理链会让扫描变慢且不稳**，先小范围验证

## 第四步：横向协议

| 协议 | 端口 | 典型用途 |
|---|---|---|
| SMB | 445 | 文件共享、`psexec` 类远程执行 |
| WinRM | 5985/5986 | PowerShell 远程管理 |
| WMI | 135 + 动态端口 | 远程查询与执行 |
| RDP | 3389 | 图形登录 |
| SSH | 22 | Linux 横向 |
| LDAP | 389/636 | 查域内对象 |

工具层面：

- `netexec`（原 CrackMapExec 的继任者）：批量验证凭据、执行命令、抓取信息
- `impacket` 套件：`secretsdump`、`wmiexec`、`psexec`
- `BloodHound`：把域内关系图化，找最短路径

### BloodHound 的价值

它不"打"，它**画图**。导入采集数据后，可以回答：

- 从当前用户到 Domain Admin 有几条路径
- 哪些组对哪些 OU 有 GenericAll 权限
- 哪台机器上有人登录过域管账号（= 内存里有凭据）

这类"权限配置错误"往往比漏洞更好用，也更难修。

## 第五步：域内常见配置缺陷

| 缺陷 | 说明 |
|---|---|
| Kerberoasting | 服务账号 SPN 可请求，票据可离线破解 |
| AS-REP Roasting | 账号关闭了预认证 |
| 委派配置错误 | 非约束委派、约束委派到敏感服务 |
| ACL 滥用 | GenericAll / WriteDACL / ForceChangePassword |
| 共享目录过宽 | 全员可写 → 投毒脚本 |
| 本地管理员密码相同 | 一台沦陷 = 全部沦陷（LAPS 未部署） |

## 检测视角（蓝队会看到什么）

这是报告里最能加分的一节：

| 行为 | 日志 |
|---|---|
| 密码爆破 | 4625 大量失败、账号锁定 |
| 横向登录 | 4624 类型 3（网络）/ 类型 10（RDP） |
| Kerberoasting | 4769 大量 RC4 票据请求 |
| 服务创建 | 7045（psexec 类工具必留） |
| 计划任务 | 4698 |
| 域内枚举 | LDAP 查询量异常、BloodHound 特征 User-Agent |

把这些写进报告，客户的安全团队才知道该配什么告警。

## 防御要点

1. **网络分段**：DMZ 到内网只开必要端口，禁止双向
2. **最小权限**：服务账号不用域管，单独 OU 隔离
3. **LAPS**：本地管理员密码随机化
4. **凭据保护**：Credential Guard、限制 LSASS 访问
5. **监控**：4662/4769/7045 三条告警线
6. **假设失陷**：按"已经进来一台"来设计检测
