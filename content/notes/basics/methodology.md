# 渗透测试标准流程与方法论

> [!NOTE]
> 这份笔记记的是**方法**，不是"打点"。所有步骤的隐含前提是：你手上有书面授权，且目标在授权范围内。

## 为什么必须有流程

新手最常见的失败模式不是"技术不够"，而是**没有留痕**：

- 扫到了 80 个端口，但记不清哪个是生产、哪个是测试
- 打进去之后不知道该干什么，最后只交了一张 `whoami` 截图
- 报告里写"存在 SQL 注入"，但复现步骤缺失，客户安全团队无法验证

流程的价值在于：**每一步都有明确的产出物**，产出物串起来就是报告。

## 七个阶段

| # | 阶段 | 核心动作 | 产出物 |
|---|------|----------|--------|
| 1 | 范围界定 | 确认域名/IP/账号/时间窗/禁止项 | 授权书、目标清单 |
| 2 | 信息收集 | 被动侦察 + 主动扫描 | 资产表、指纹表 |
| 3 | 威胁建模 | 画架构图，标出信任边界 | 攻击面清单 |
| 4 | 漏洞验证 | 只验证，不深入利用 | 带证据的漏洞条目 |
| 5 | 受控利用 | 证明影响，最小化破坏 | 影响证明（截图/日志） |
| 6 | 后渗透 | 权限维持的**可行性**评估 | 横向路径图 |
| 7 | 报告与复测 | 复现步骤 + 修复建议 | 报告、复测结论 |

### 1. 范围界定

授权书里必须写清楚的东西：

- 目标：域名、IP 段、App 包名、具体账号体系
- 时间窗：几点到几点可以打（生产环境通常只允许夜间）
- **禁止项**：社会工程、DDoS、物理入侵、第三方托管服务（云厂商的基础设施通常不在范围内）
- 数据处理：拿到的数据如何存储、何时销毁

> [!WARNING]
> "客户口头说可以"不是授权。没有书面范围，你做的每一件事都是在赌。测试云上资产时尤其注意：**你租的服务器在范围内，云厂商的底层不在**。

### 2. 信息收集

分两条线并行：

- **被动**：不直接接触目标。证书透明日志、DNS 历史、代码托管平台泄露、搜索引擎。
- **主动**：直接发包。端口扫描、目录爆破、指纹识别。

细节见 [[recon-passive]] 与 [[recon-active]]。

### 3. 威胁建模

把收集到的资产画成图，然后只问一个问题：**谁能跨过哪条边界？**

- 互联网 → DMZ：暴露面有多少？
- DMZ → 内网：有没有单向信任？
- 普通用户 → 管理员：权限边界在哪校验？

这一步决定后面 80% 的精力该花在哪里。没有建模就开始扫目录，通常是在做无用功。

### 4. 漏洞验证

原则：**能证明存在即可，不要顺手把数据拖下来**。

- SQL 注入：证明可以布尔判断或报错，不必 dump 全库
- 文件读取：读到 `/etc/passwd` 前几行即可，不要读业务数据
- 命令执行：`id` 或 `whoami` 足够，不要留文件

### 5. 受控利用

需要证明"影响"时才继续深入，例如：

- 从低权限用户到管理员（证明权限模型失效）
- 从 Web 服务器到数据库（证明网络分段失效）
- 从一台主机到域控（证明横向移动可行）

每一步都记录**时间、命令、返回**，这是报告的证据链。

### 6. 后渗透

重点不是"能拿多少台"，而是评估：

- 权限维持是否可行（计划任务、服务、账号）
- 横向路径有几条，哪条最短
- 有没有被检测到（蓝队视角的日志）

### 7. 报告与复测

见 [[report-writing]]。一句话原则：**执行摘要给老板看，技术细节给工程师看，两者不能混**。

## 时间分配参考

以 5 天的人天为例：

| 阶段 | 占比 | 说明 |
|------|------|------|
| 范围与准备 | 10% | 环境、VPN、工具、授权确认 |
| 信息收集 | 25% | 通常被低估，实际最花时间 |
| 验证与利用 | 40% | 核心工作 |
| 后渗透 | 10% | 视目标而定 |
| 报告 | 15% | 不要留到最后一天赶 |

## 常见错误

- **只扫不记**：所有命令的输出都要落盘，`tee` 是你的朋友
- **忽略业务逻辑**：越权、支付篡改、并发问题往往比 RCE 更值钱
- **越界**：为了"多证明一点"去碰范围外的资产
- **不留证据**：截图没有时间戳、请求没有原始报文，复测时无法对齐

## 一份可复用的检查清单

- [ ] 书面授权与范围确认（含禁止项）
- [ ] 目标资产清单（域名 / IP / 端口 / 应用）
- [ ] 测试环境与出口 IP 报备
- [ ] 被动侦察完成，子域与历史解析已归档
- [ ] 主动扫描完成，结果已去重
- [ ] 攻击面清单与信任边界图
- [ ] 每个漏洞都有：位置、类型、证据、影响、修复建议
- [ ] 后渗透可行性结论
- [ ] 报告初稿 + 内部复核
- [ ] 数据销毁确认
