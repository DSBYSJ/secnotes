# 授权边界：什么能做，什么不能做

> [!WARNING]
> 以下内容是学习笔记，不构成法律意见。真实项目请以正式合同、授权书与法务意见为准。

## 一条底线

**没有书面授权，任何针对他人系统的探测都是违法风险**，哪怕只是 `nmap` 扫端口。

国内主要涉及：

- 《网络安全法》—— 网络运营者与测试者的基本义务
- 《刑法》第 285 条 —— 非法侵入计算机信息系统、非法获取数据
- 《刑法》第 286 条 —— 破坏计算机信息系统

"我只是测一下有没有漏洞"不构成抗辩理由。**是否授权**才是分界线。

## 授权书必须包含的六项

| 项 | 内容 | 缺失后果 |
|---|---|---|
| 委托方 | 公司全称、盖章 | 无法证明谁授权 |
| 目标 | 域名、IP 段、App、账号 | 越界时无法自证 |
| 时间窗 | 起止日期，精确到小时 | 半夜打生产被当成攻击 |
| 方式 | 黑盒/灰盒/白盒，是否允许社工 | 用了社工即违约 |
| 禁止项 | DDoS、物理、第三方系统 | 打崩云服务要担责 |
| 数据处理 | 存储位置、保留期、销毁方式 | 数据泄露责任在你 |

## 常见越界场景

### 1. 共享基础设施

你测试的 SaaS 跑在云上，扫端口扫到了云厂商的元数据服务或相邻租户。**云平台本身不在范围内**，这类操作应立刻停止并记录。

### 2. 子域归属不明

`test.example.com` 可能托管在第三方外包商那里。处置方式：

- 先查 DNS 与证书，判断归属
- 归属不清的资产，**写进报告的"未测试"清单**，而不是"先打了再说"

### 3. 供应链跳转

从 A 公司的系统跳到 A 的供应商 B。即使技术上可达，B 也不在授权范围内。正确做法是：证明"可以跳转"，但不实际进入。

### 4. 数据过度采集

验证 SQL 注入时把用户表 dump 下来——这已经超出"证明漏洞存在"的必要范围。合规做法：只取结构或前几行，且立即删除。

### 5. 权限维持

客户没要求"评估持久化能力"，你却留了后门方便下次进来。这是**最严重的红线**，等同于入侵。

## 自保动作清单

- [ ] 授权书原件存档（扫描件 + 纸质）
- [ ] 测试出口 IP 提前报备给客户 SOC
- [ ] 每次连接保留时间戳日志
- [ ] 高危操作（提权、写入、重启服务）事前书面确认
- [ ] 遇到范围外资产，立即停止并书面告知
- [ ] 项目结束提交数据销毁确认

## 靶场与自建环境

合法练习的三个方向：

1. **在线靶场**：HackTheBox、TryHackMe、PortSwigger Academy、VulnHub（下载到本地）
2. **本地靶场**：DVWA、Juice Shop、sqli-labs、upload-labs、Metasploitable
3. **自建环境**：自己买 VPS 或本地虚拟机，随便打

> [!TIP]
> 判断一个环境能不能随便打，只问一句：**这台机器是不是我的，或者我有没有这台的授权？** 两个都不是，就停手。
